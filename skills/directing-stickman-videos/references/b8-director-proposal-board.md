# B8 分镜导演提案板：制作前的用户确认关口

适用于 B8 新片及分镜、场景、动作因果的修改。续接工程先读 checkpoint，复用仍有效的批准，不重做无关镜头。提案板用于让用户判断故事与镜头是否成立；素材美观、角色认可、技术检查通过均不能代替此项确认。自动执行[默认视觉检查](b8-visual-quality-gates.md)，仍沿用现有提案、准确姿势和样片批准阶段，不另加用户审批关口。

## 执行顺序

1. **锁定输入。** 记录本次范围、原文/完整配音的实际时间、已确认人物与移动参考、素材指纹、已有批准及缺口。不为迁就新分镜擅改台词、重录、变速或付费生成。
2. **先审因果，再画板。** 按下文逐镜审查故事规则、主要动作和附带接触。发现矛盾先修分镜；未确定的边界标为“建议/待确认”，不能自称原作设定或已获批准。
3. **制作可审阅的导演提案板。** 使用现有素材、构图草图和关键姿势说明；必要的新素材与费用列作缺口，不在此阶段默认付费制作。覆盖本次完整范围，交付可点击的板图、逐镜表及待定项。按目标画幅原生绘制构图：9:16 先安排可见动作、接触/结果与全身或近景意图，检查头冠、脚底落地、半身贴图边界和字幕安全区，不能把横屏居中裁切直接当竖屏提案。将所有出场角色与同一 B8 参考放在一张 cast/style board，比对线重、明暗、头身比例、全身/表情及脸手简化程度；沿用 B8 已选画风，只确认本故事的具体设计，不反复询问是否选 B8。已有全部角色有效批准时直接复用，新增角色与已确认角色并排核对。明确草图与最终角色姿势、画面质感的区别。
4. **交用户确认。** 必须先给用户看具体提案板；只有用户明确确认对应版本的分镜方案，才进入该范围的新素材/准确关键姿势制作及获授权动画。不得把无回复、继续讨论、角色好看或旧成片批准当作新提案批准。提案确认不自动授权付费、扩片或发布。
5. **再做动作与动画。** 按[默认标准](b8-approved-standard.md)优先使用完整绘制的动作单元；先核对准确的接近、接触、变化、结果、反应姿势及部位连接；有争议的动作先做必要短测试，再按授权制作。保留样片和最终成片各自的观感验收，板图批准不等于动画验收。

用户可以明确豁免本次提案关口；只记录其实际授权，不把一次豁免变成永久取消。

新故事尚无定稿或录音时，可以先写待确认文案与粗节奏提案，时间标为暂定；不要把先付费配音当作出提案的前提。进入最终动作/字幕对齐前，再按获准的实际录音校准。已有完整录音的改稿继续锁定原文原速，不借此重录。

## 提案板最小内容

镜数和场景数服从故事，不设统一数量或固定时间模板。每镜按实际台词记录：

| 内容 | 用户应能判断的问题 |
|---|---|
| 时间、原文、信息增量 | 这句为什么用此镜？前后多知道了什么？ |
| 场景、景别、空间连接 | 是否一直围着同一桌/同一侧面？新场景如何相连，何处允许时间省略？ |
| 目标画幅构图、独立层、有限运镜与停点 | 本比例下动作/接触/结果是否可见？全身或近景意图是否明确？头脚、贴图边界与字幕是否安全？人物、道具、近远景各自做什么，是否只有成图裁切缩放？ |
| 全角色画风与身份 | 主配角是否共用笔触、明暗、比例语法和手部简化程度，同时保持各自身份？ |
| 关键姿势与反应 | 身体自身哪只手，与画面哪侧进入是否分清？掌心/拇指、握点、腕—前臂—肘回接身体哪侧、袖口与遮挡是否成立？能否与完整姿势对上？变化后角色如何反应？ |
| 共同空间与运动 | 脚底/地影、手物、物体支撑及背景是否共享合理坐标与相机？全路径和停点会不会脚滑、漂浮、同平面错速、底图无动机横移或停不住？固定镜头可以成立。 |
| 规则触发与状态链 | 为什么发生变化，作用到哪个物体，下一镜保留什么结果？ |
| 复用/新增/待定 | 哪些素材已确认，哪些只是草图，哪些决定仍须用户判断？ |

## 故事规则和接触审计

仅在故事实际涉及魔法、诅咒、机关、传播等规则时建规则表，不替普通动作虚构世界观。区分已确认原文事实、用户指定、制作建议和未知；没有依据的豁免不能拿来补漏洞。

- **触发与范围：** 谁以何种接触/动作触发？作用对象如何界定为一个物体？连着树的枝条与已经落地的断枝不是相同范围；不能为当前构图任意截断效果。
- **附带行为同样生效：** 扶桌、拨帘、靠柱、抓椅背、换手、拾取、放下、食物碰嘴等都列入；不能只审旁白点名的道具。冲突可删除不必要接触、调整调度或画出一致的后果；不能临时给人物开关能力、加免疫手套或豁免某件家具。
- **直接与间接接触：** 握杯不等于碰到杯内的酒；金化道具落到桌上是否传导也不能临时决定。需要的边界先提出供确认，不擅自假设只有指尖有效、隔物也有效或衣物免疫。
- **时间与结果：** 首次接触、变化起点、变化完成和反应的次序可读。已经握着的物体不能无因等到下一句才触发；金化后不能切回原材质。颜色扫过只是表现时间，不能偷偷改作用范围。
- **时窗与物性：** 按实际配音给主要动作、必要转移和反应分配时间，不能把过多动作塞到切点后宣称已展示；超载时先简化调度或调整画面切点，不擅改原声。状态变化同时约束形状和运动：例如液体凝成金属后须保持凝固瞬间的形状，不能下一镜又像液面自行找平。
- **跨镜账本：** 同一道具记录持有者、握点、位置、材质与最后可见状态；放下/掉落须可读。明确时间省略时可以不叙述每项收拾动作，但不得在下一镜凭空把物品摆到某处，并宣称已交代转移。

审计表至少包含 `shot / object / contact_agent / direct_or_indirect / first_contact / effect_scope / before_after / next_state / basis_or_pending`。没有发生接触的关键避让也记明可见间隙，便于关键姿势与运动路径复验。未知边界若会改变当前画面，进入提案待定项，不能悄悄进入制作。

## 批准与恢复记录

在原项目 checkpoint 保存提案版本、板图/逐镜表/规则表的绝对路径和 SHA-256、用户确认消息/日期、批准时间范围、已确认规则与仍待定项、下一步、运行任务。各状态分开：`character_appearance`、`director_proposal`、`keyposes`、`animation_sample`、`final_film`。

导出报告自动带逐镜 `quality_review`，提案的共同画风/构图项初始 pending；后续关键姿势增加手臂方向，实际视频再核空间运动。实际审阅者记录镜号/时间、具体说明与绑定报告 artifacts 的 SHA-256 证据，不能为过门槛批量填 accepted。现有 `approve` 写入新批准前核查这些记录并冻结独立报告快照，后续补审原报告不撤销旧局部批准；视频项须引用实际编码 MP4。内部审阅完成仍须对应的真实用户确认，`validate PROJECT --review REPORT` 只是只读终检，不写批准。横屏确认不自动覆盖新竖屏构图，但未改变范围的有效历史批准保留。

分镜、规则或关键动作改动后，标出受影响镜头并重新给用户确认对应提案；沿用未受影响的批准。没有审核过的姿势或动画保持 pending，禁止为通过检查填成 approved。发现新逻辑冲突时先修提案和状态记录，再继续受影响镜头。
