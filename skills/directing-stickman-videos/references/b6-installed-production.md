# B6 after installation: make the requested film

The user's outcome is a new film at the demonstrated drawing/animation quality. A gallery, prompt collection, copied asset folder or successful re-encode of V90 is not that outcome. Treat the Skill as an agent-operated production workflow: the user supplies the topic/story, duration and format; the agent performs planning, asset preparation, binding, animation, sound, inspection and delivery. Do not ask the user to fill project JSON or manually assemble the engine.

## Default route

B6 defaults to the user-approved bundled **Archivo Black** caption font, preserving the established caption geometry, outline, raster and phrase switching. New-story production does not require Arial or Arial Black. Initialization records the actual project font and provenance. Locally installed original fonts remain optional for historical V90 typography reproduction; see the [V90 recipe](b6-hong-kong-v90.md).

Read the [Sample 1 detailed acceptance matrix](b6-sample-1-acceptance.md), B6's drawing/light, native-format, character-binding and [motion execution/review](b6-motion-review.md) guides before authoring. Check the current request and existing approvals first. Reuse known story/format/voice choices; only ask for missing decisions that change production. Follow existing cost/provider authorization for new still images and speech. Code renders animation; a video generation model is not the motion fallback.

**Portrait (9:16) works best. The strict primary standard is Sample 1's portrait Eiffel V44**, installed in full at `assets/b6/reference/eiffel-portrait-v44.mp4`. `assets/b6/style-standard.json` locks its hash, relative limb stroke, brushwork, light and animation criteria. The initializer copies that standard to `quality-target.json` and the exact portrait movie into the new project, including when the requested output is landscape. Match arm thickness at comparable views and the same head width; do not inherit Sample 2's finer line weight. The installed `assets/b6/reference/hong-kong-v90-20s.mp4` is secondary binding/engineering evidence. The landscape Eiffel example can inform format adaptation but does not replace the primary portrait standard. Do not rely on an outer repository gallery path after installation. Reference clips are comparison material, never footage pasted into the new film.

The normal B6 initializer now copies the **complete V90 painted engine** into a new authoring project:

```bash
node scripts/autopilot.mjs doctor --style B6
node scripts/autopilot.mjs init /absolute/new-story --style B6 --ratio 16:9
```

The agent handles environment setup as well: Node 20+, FFmpeg/FFprobe, the Skill's locked npm dependencies, and Python 3.9+ with NumPy/Pillow/OpenCV. Use `npm ci` in the installed Skill if its Node dependencies are absent. For missing Python packages, use a project virtual environment and the bundled `assets/b6/hong-kong-v90/requirements.txt`; select that interpreter through `B6_PYTHON` or `--python`. Run the B6-specific doctor again after setup. Follow the host's installation/network permissions, but do not send the user away to assemble the renderer or diagnose package imports. The isolated-install test still relies on an available compatible runtime; it does not imply a Skill folder bundles Node, Python or FFmpeg binaries.

It creates `project.json`, `story.json`, `captions.json`, `scene.py`, `formats/landscape.json`, standalone `run.py`, `motion_review.py`, `caption_renderer.py`, `b6_space.py`, `b6_puppet.py`, trusted `b6_asset_roles.py`, empty `characters.json`/`characters/` and a locked `quality-target.json` with a project-local reference movie. `engine/` contains the full locked source/art/font/rig package. `--ratio 9:16` or `both` creates separate native plan slots, not an automatic portrait conversion. Initialization creates no finished scene, voice, synthetic approval or paid call. The agent continues authoring; initialization is never the deliverable.

`--example hong-kong-v90` is solely the explicitly requested unchanged 20-second reproduction route; its report says `purpose: example-reproduction`, never a new-story success. `--example blocking-calibration` explicitly selects the retired six-second diagnostic renderer. Its frames/previews carry a visible diagnostic label and its `approve`/`render` commands are permanently disabled by renderer identity. Changing `stage`, deleting `technical_fixture` or adding review notes cannot promote it. **Never use a copied test, old film or reference shot as the requested new B6 story.**

### Media roles before authoring

Keep three purposes separate: **production** is the requested authored story; **diagnostic** exercises code/geometry only; **example-reproduction** intentionally recreates the named unchanged example. Default initialization sets `purpose: production` and remains unimplemented. These labels cannot grant permission to reuse protected media: the runtime derives diagnostic/example status from actual known scene bytes and renderer/mode, and treats downgrade flags only as an additional restriction.

The trusted portable `b6_asset_roles.py` inventories the bundled B6 reference/test/example images, audio and movies by content hash. It checks story dependencies and registered character-package files, so copying or renaming them does not make them production art. It also checks actual local media reads before writing rendered frames: the comparison movie allowed by `quality-target.json` cannot be opened by `scene.py` as a background, sprite or footage layer. Do not strip the guard, omit dependencies, relabel old scaffolds, or remove fixture markers to get a pass. Old engine source/assets stay intact for implementation study and explicit reproduction; ordinary new-story execution does not expose its old `context.engine` performance object.

Actual production reads also check project-external media by content, not just a short filename-extension list: known protected bytes, common audio/video headers and every installed Pillow image decoder are checked even with a missing or misleading extension. Project-local read/write handles remain subject to protected-content checks. Installed Python library/package resources stay available; story media must be prepared as project-local inputs. This catches ordinary renamed-file reuse, not all transformed art or malicious native I/O.

Production scene import and each `frame()` call also reject ordinary audited process launches (`subprocess`, shell commands, spawn/exec/fork). A child decoder would otherwise bypass the parent's file-read audit. Prepare new media during asset production as project-local PNGs and list them in `project.inputs`; do not start FFmpeg or another decoder from scene code. The trusted runner still starts its encoder/muxer outside scene execution, and explicit example reproduction retains its existing behavior. This bounded misuse check is not a sandbox for malicious Python or native code.

References may still be inspected, compared or supplied to an authorized still-image workflow to create **new story-specific paintings**. Keep their provenance and the new outputs' paths/hashes. An existing user-approved production character may be reused when the user requested that character, with the original approval and compatible action/view scope; the bundled demo/test roles do not qualify. Hash checks catch unchanged bytes, not every crop, repaint or re-encoding. During the mandatory 35-item actual-media review, verify that every setting, visible identity/action, narration and prop fits the requested story, and inspect any transformed/derived reference use. An arithmetic/hash pass never establishes drawing or story quality.

## What the agent must produce

1. **Story and native shots.** Write the actual narration/semantic beats. Design the requested format's own staging, camera, occlusion, action and transitions. Give each shot a reason: environment/ensemble, setup, contact, detail or reaction. A protagonist need not appear in every shot. Avoid repeated push-ins and unexplained subsecond information flashes.
2. **Art and wide-world package.** Inspect Sample 1 portrait, the supporting approved character and suitable V90 painted layers as style/engineering references; do not copy bundled test/reference layers into the new story. Write a story-specific look brief and still prompts using `b6-art-direction.md`; retain irregular ink, unified head/body brushwork, meme expressions, single painted stick limbs matching Sample 1's relative stroke weight, and warm soft light. Record the same-head-width limb comparison; do not make the lines uniformly thinner or use a global pixel width as the style rule. Change cast/era/setting deliberately. Make a genuinely broad, dressed world with front/middle/back layers and enough overscan for the intended camera. A filter or an old background is not a replacement for story-specific art.
3. **Bound characters and action code.** Reuse a compatible approved identity/action first. Otherwise prepare the required angles, expressions, cutouts, actual sleeve/hip/sole pins, fixed bone lengths and occlusion masks. Use the installed executable puppet rig, paint/compositor and world-space primitives; do not invent another circle-head/vector renderer. Test contact/turn/reaction at a fixed camera, then with the native camera. New silhouettes need new calibration; copying another character's numeric pins is not transfer of style.
4. **Original-speed sound and captions.** Use the approved or newly authorized voice and mixed track, pin its exact hash and actual duration. Align complete captions to actual speech at semantic boundaries. Use the copied `caption_renderer.py` and approved English Archivo Black profile (`eiffel-v44-portrait-archivo-black-v1` for portrait), including font identity, placement, ink color, 3× raster and hard phrase switching; review decoded glyphs/transitions as well as the config. Design landscape separately with a native-layout reason. The default portrait profile supports English; a different language/design requires an explicitly named implemented profile, verified font/glyph coverage and repeated native/runtime validation. Recording a reason alone does not enable an override, and changing the primary manifest cannot lower the gate. An unchanged/safe/synced cue does not establish a match to the approved caption profile. The agent handles this work. The runtime muxes supplied sound; it does not synthesize/mix it or infer word timings.
5. **Representative preview and completion.** Render a finished 5–10-second stress segment containing the riskiest contact, reaction and camera/layer relationship. Inspect actual-size crops, consecutive decoded cuts and intended-speed playback under the [motion review gate](b6-motion-review.md). Verify the promised spatial move, body-supported action, eyeline/emotion and camera landing against the selected reference. Repair visual gaps, arm ownership, missing limbs, reversed elbows, sleeve/table occlusion, foot drift, facial mismatch and overscan before extending. Technical checks, motion/visual review and user approval are three separate results. Deliver video, project and folder link. Continue the authorized film after actual review; do not publish without the user's instruction.

## Authoring interface and commands

Set `stage: authored`, real `duration`, original-speed `voice.path`/`sha256`, exact `story.narration`, semantic `captions.json`, and the requested native plan. Lock `project.quality_target` to a project-relative reference manifest with the actual comparison video's hash and relevant time ranges; follow the [motion review contract](b6-motion-review.md#runtime-evidence-contract). Each plan has dimensions, the explicit ratio-specific `caption` profile from `quality-target.json` → `public_caption_profiles["archivo-black"]` (including a native-layout reason for landscape), and continuous shot coverage with `composition`, `action`, `camera` and `transition`. The native plan must declare `cast_inventory: [{id, role, shot_ids}]` for every visible identity, including static people painted into the background. Use `[]` only for genuinely unpeopled footage. This is mandatory input, not an optional review note; the review inventory must match the identities and shot memberships intersecting the actual preview range. List custom local art/helper-code dependencies in `project.inputs` so they are audited and fingerprinted.

For new cast/actions, the project-local `scene.py` exports `frame(t, context)` and returns the final `context.puppet_runtime.RenderResult` at native dimensions. Use the [executable puppet API](b6-puppet-api.md). `characters.json` is mandatory and must cover the native cast exactly once: `actors` map each ID to its project-local per-view package and declared tested views; version-2 projects currently forbid `rigid_cast` exceptions because intact-source declarations do not establish actual pixel coverage. Include every visible person in the registered puppet path. The project-local runtime hash must match the installed trusted implementation before validation imports it.

Calibrate the actual head/body/cuff art, sleeve outlet, fixed lengths, single-stroke weight, near/far order and five FK poses for every view. Keep the same `Puppet` instance over consecutive frames for continuity checks. A contact target closes through bounded planar IK; there is no invented Z, length stretch, elbow-side switch or silent clamp. Use `arm_actions` so one reaching arm does not raise the idle arm. At a real authored cut/view transition, explicitly declare it; a view swap is not an automatically generated in-between turn drawing.

One `ContactTimeline` drives both the actual paper and each holder's grip. New scenes pass final background/foreground into `render_scene`; its actual visible alpha and part IDs travel with `beauty`. The production runner verifies package/view identity, arm/leg inventory, real cuff-outlet connection, upper/forearm/hand visibility and connection, feet, independently projected prop contact and immutable final evidence. Do not supply a disconnected test skeleton or replace `beauty` after these checks. List all project art/code in `inputs`; package JSON and all of its assets are fingerprinted automatically. Detailed fitting, rendering and negative checks are in [character binding](b6-character-binding.md).

The older `context.engine.draw(source_time, camera=(cx,cy,uniform_scale))` route remains only for the frozen installed 7.5-second landscape source-reuse example, with `character_system.mode: locked-v90-performance`. The scene, native plan and locked engine fixture must match embedded hashes; a scope reason alone cannot grant an exception. New character bindings are forbidden, and each frame must actually use the locked source draw. Old version-1 numeric-binding/test projects are diagnostic compatibility inputs only, not an alternate production route. They cannot be approved or rendered as a new finished story.

Track ownership through the whole action, including approach, regrip, shared handoff, release and the final hold. Every frame in which a hand supports a prop needs its contact row; an empty inventory is valid only when nothing is being held. If a prop splits, each loose part needs a supporting grip until it is visibly gathered into a shared bundle. Inspect consecutive decoded frames around handoffs as well as selected stills: a zero endpoint error cannot prove correct occlusion, a natural elbow or a readable gesture.

```bash
node scripts/autopilot.mjs validate /absolute/new-story --ratio 16:9
node scripts/autopilot.mjs preview /absolute/new-story --ratio 16:9 --trusted-code --start 0 --seconds 7.5 --output outputs/preview-01
# The same project works independently of the installed Skill/history folders:
python3 /absolute/new-story/run.py preview /absolute/new-story --ratio 16:9 --trusted-code --seconds 7.5 --output outputs/preview-02
```

Prepare the runtime's `review-pack` for the exact preview and complete its shot observations against actual media as described in [motion execution and review](b6-motion-review.md#runtime-evidence-contract). It creates decoded shot/reference clips, frames, an index and a pending `motion-review.json`. Pending or needs-repair findings must be resolved before recording the preview as ready. They also keep the production task active: repair dependencies or implementation, render a fresh local iteration, review its real playback against Sample 1, and repeat. Do not stop by delivering a known failing preview and waiting for the user unless the user requested an intermediate look, explicitly stopped work, or an evidenced external blocker prevents dependent progress. A new charge, upload or publication still follows its original authorization boundary. The schema-v3 review requires all 35 independent Sample 1 subchecks with actual candidate/reference observations, not only eight broad pass labels. Inspect complete chains for all active identities/views, relevant contacts frame by frame, neighboring cut frames, native-size detail/safety and full-range original-speed AV. The review file checks evidence freshness/completeness; it does not judge visual quality automatically. Iterative previews remain available for repairs.

Preserve `.b6-review-history/` with the project. Failed `check-review` results and explicit predecessor imports register an independent frozen history; later packs inherit its open findings even without `--review`. This administrative history stays outside `project.inputs`. A claimed implementation repair needs changed source and rendered pixels; a genuine prior misreport needs an explicit `review_correction` explanation and actual re-observation instead.

Only after a current completed motion review and the actual preview decision, use `approve --report outputs/preview-01/report.json --review outputs/review-01/motion-review.json --note` to record the user's real decision, then `render`. Approval is per ratio, reviewed video and input fingerprint. Never approve the agent's own test, a technical fixture or the old film. Any change to reviewed source/art/audio invalidates the corresponding approval and review. Files and outputs must remain project-local; existing outputs are not overwritten. Encoded outputs include SRT/VTT sidecars derived from the same semantic cues as the burned-in captions, clipped and offset to the reviewed range. Validation checks hashes/data without importing the authored scene; rendering explicitly executes trusted local Python.

Version 1 is retained here for this historical package's bounded structural checks; it does not bypass version-2 production head/neck and pixel checks. Inspect the real performance and sleeve crops before using its pattern for another cast. Run `python3 tests/b6_puppet_test.py` for actual-pixel injected failures. This fixture tests binding/transfer plumbing, not the 35-item drawing/camera/audio acceptance of a finished story.

## Evidence required before a public capability claim

Keep these three results separate:

- **Package completeness:** a clean directory renders V90 without reading old workspace media.
- **Reusable authoring:** a different duration/order/camera works through the installed default authoring entry, with current drawing/rig checks and original-speed supplied audio. Reusing existing actions does not prove arbitrary new-action fitting.
- **New-story quality:** a new brief produces its own character/setting as needed, correct native staging, calibrated actions, actual sound and a visually accepted preview. The Skill must do this work, not merely claim that the first two results guarantee it.

The local V90 package currently establishes a 16:9 reference performance. Portrait composition, unseen characters and unseen actions require their own tests. Missing provider access/artwork or an untested native plan must be stated accurately; never silently degrade the output. Do not describe the module as universal, one-click guaranteed quality until that claim has actually passed independent new-brief tests.
