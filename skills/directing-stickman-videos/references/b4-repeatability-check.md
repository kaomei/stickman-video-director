# B4 · Portable production evidence check

Read after the B4 visual, opening, [picture-animation](b4-picture-animation.md), [typography acceptance](b4-typography-acceptance.md) and audio contracts. This read-only checker validates project evidence and timing, **not** animation quality, art quality or actual listening. B4 rendering uses the [shared installed runtime](autopilot-runtime.md#b4-production-tracks); the ledger complements its media/timeline validation. Use a fresh external project and an isolated copy of this Skill for an installation rehearsal; never depend on old chat context or absolute developer-machine paths inside the package.

Run from the installed Skill:

```bash
node scripts/b4-production-check.mjs /absolute/project/b4-ledger.json
```

The project-local JSON contract is `schema: b4-production-ledger-v1`, `style: B4`, with `fps`, `duration_frames`, `script`, `voice`, `opening`, `assets`, `shots`, `ambience`, `audio_cuts` and `critical_sfx`. Portrait ledgers additionally declare the actual output `width` and `height`. Paths below resolve inside the external project, never inside the Skill. Each referenced file must exist; the checker never runs source-provided commands or fetches URLs.

- `script`: `file`, `sha256`, and nonempty `authorization` identifying the user's production instruction for this exact script. The UTF-8 text must be nonblank, including in planning mode. Credit approval alone is not script authorization. This is recorded evidence, not an authentication or permission-granting mechanism; verify it against the actual conversation before generation.
- `voice`: `name: Brian`, `id: nPczCjzI2devNBz1zQrb`, `file`, `sha256`, and `input_script_sha256` matching `script.sha256`; retain approved native settings in a separate project cast manifest. The input hash records which script was sent, not a claim that the audio transcript was automatically verified. An explicit narrator override must record `user_override` and its actual identity; do not mark an unapproved substitute Brian.
- `opening`: `question_groups` (two complete semantic strings), `group_start_frames` (setup first, full remainder second), `remainder_entrance: together`. Landscape `b4-hook-v1` retains `left_half_shadow: true`. Native portrait declares `preset: b4-portrait-poster-v1`, `layout: portrait-poster`, and true values for `top_breathing_space`, `lower_picture_unobscured`, `native_portrait_art`, `whole_payoff_settle`, `short_emphasis_line`; record the actual portrait `width`/`height`, not a false landscape-shadow claim. These fields record production evidence, not visual proof. Different user-approved treatments require an explicit `user_override` reason.
- `assets`: unique `id`, `file`, `sha256`, `provenance` (`new_generated` or `project_owned`), `references` (bundled reference IDs actually submitted), `prompt_file` (the saved complete submitted prompt), and `prompt_sha256`. A fresh-story test sets `fresh_test: true` and only uses `new_generated` story art. Canonical style references are allowed in the separate `references` input list; they cannot be the story image in `file`. The [asset-origin boundary](b4-asset-origin.md) rejects known reference/showcase copies regardless of the declared provenance, filename or `reuse_reason`; old film frames are not new art.
- `shots`: contiguous `start_frame`, `end_frame` (exclusive), `asset_id`, nonempty `meaningful_view`, `beat` and per-shot `picture_motion` below. Every complete shot lasts at most three seconds; fit events, actual voice pauses and readable results within that hard maximum. An unchanged principal-picture state cannot exceed three seconds across adjacent shots either. Renaming `meaningful_view`, re-cropping, subtitle updates, micro-zooms and decorative effects do not establish a new state, restart its dwell timer or supply animation.
- Each ledger `shots[].picture_motion` records `kind` (`local_action`, `state_reveal`, `environment` or `motivated_hold`), `intent`, `before` and `after`. A non-hold entry additionally needs an actual in-shot absolute `start_frame`/`end_frame` and either `motion_file`/`motion_sha256` or `motion_plan_file`/`motion_plan_sha256`. A JSON plan uses `schema: b4-picture-motion-plan-v1`, this shot's `asset_id` and matching absolute `start_frame`/`end_frame`; its `events` identify `subject`, `property`, `from`, `to`, `start_frame`, `end_frame`. The declared event must change state within its interval; a blank/no-op plan is not evidence. A `motivated_hold` needs `reason` and `support_shots` naming adjacent non-hold shot indices, and must remain within the three-second shot/state limits. Neither `exceptional_hold` nor an author-written `user_approval` grants a longer shot. This frame-based ledger evidence is **not** the runtime's `picture_motion.shots` rendering declaration; author that [layer/region/absolute-seconds plan](b4-picture-animation.md#runtime-picture-plan) too and keep the two consistent. Neither a saved plan nor a motion-file hash proves its final MP4 effect.
- `ambience`: intervals covering the programme except declared `audio_cuts`, each with `start_frame`, `end_frame`, `file`, `role: subtle_bed`. Crossfades/overlaps are allowed; a gap is not. `audio_cuts` record the same interval fields plus `reason` and `return_trigger`.
- `critical_sfx`: each scripted consequential event has `id`, `file`, `sha256`, `trigger`, `perspective`, `rights_status: cleared`, `review` (`pending` or `pass`). An empty list must explicitly state `no_critical_sfx_reason`; do not omit a real event to pass.

Machine checks reject absent/blank/unrecorded scripts, stale voice-input script hashes, missing files/fingerprints, wrong voice identity, stale/missing canonical references, missing complete style prompt, known reference/showcase artwork relabeled as story assets, absent/invalid picture-motion evidence, uncovered timeline/bed and unreviewed or uncleared critical effects. `--planning` permits missing generated media and pending cue review, but still requires the authorized script and planned picture events, and reports mode `planning_only`. Both planning and normal evidence checks report `status: technical_only`, `delivery_ready: false` and unreviewed visual acceptance; neither is final acceptance. Report the mode honestly.

The ledger is **not** the opening renderer or visual acceptance gate. In the shared runtime, author the [fixed opening](autopilot-runtime.md#b4-fixed-opening), then run `validate` and `preview`. Review `opening_visual` and the encoded opening contact sheet in the export report: they check painted state changes, the picture reveal's intermediate frame, fixed title timing and visible scale-settle against actual MP4 frames. `approve` decodes the current video again, so changing a report to `pass` cannot replace the missing animation. Do not report static cuts/timed text, a hard before/after switch, decorative motion or a keyframe count as proof of micro-animation. Preserve human review for semantic meaning, acting, fear, anatomy, legibility and synchronization; a diagnostic pass is not creative acceptance.

Complete the separate independent [encoded picture review](b4-picture-animation.md#encoded-evidence-and-independent-picture-review) for every shot and [text review](b4-typography-acceptance.md#encoded-evidence-and-independent-acceptance) for every text moment/caption in the actual MP4. Picture review includes semantic local motion/intermediate states, contact anatomy, continuity, cross-section reuse/pacing, mandatory current-story asset-origin observations and complete continuous playback. Typography review cannot certify picture animation. For portrait, inspect both tracks at phone size, including the settled title, unobscured principal picture and next-shot transition. Check source material/causality, full-mix sound and user review separately; the selected reference does not automatically approve a new story. File hashes establish only which file was checked; self-reported provenance and view IDs still require human/source review. A valid ledger is necessary evidence, not proof of an attractive or stable long film.

Code-authored/custom-rendered B4 must connect its actual final MP4 to both [picture evidence/review](b4-picture-animation.md#custom-renderers-and-production-ledger) and [typography evidence/review](b4-typography-acceptance.md#encoded-evidence-and-independent-acceptance). Supply the renderer's draw/picture-isolation and draw/text-registry adapters; the ledger alone contains no MP4 review. If either adapter/evidence is unavailable, that track remains unreviewed and the output cannot be delivered as meeting B4's visual acceptance. Do not bypass the shared gates with a separate manifest, a successful ledger check, an added GIF or a hand-written passing result.

For every B4 export also run `node scripts/b4-opening-audio-check.mjs /absolute/final.mp4` and save the JSON externally with that file's fingerprint. This decodes the actual opening and flags a delayed perceptible onset or token-hit/near-silent gap; the ledger's ambience coverage cannot establish audibility. Resolve any diagnostic finding or record a story-motivated silence exception under the [first-frame audio gate](b4-audio-direction.md#first-frame-audio-gate). A diagnostic pass is not a listening/creative acceptance pass.
